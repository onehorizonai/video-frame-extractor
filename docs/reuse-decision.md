# Video frame extractor reuse and differentiation check

**Decision: hold public readiness pending the validation gate.** The current implementation is a reviewable prototype. Its narrow possible advantage is choosing a subset of previewed frames for a ZIP, with requested and available decoded timestamps shown separately. That advantage has not yet been shown to matter in a tested creator workflow, and Framed overlap remains unknown. Do not claim that free local alternatives are absent or that this extractor is frame accurate.

**Framed reuse check.** Framed appears as a separate internal One Horizon workspace in the accessible monorepo's product reporting fixtures, but no Framed source, owner, license, or frame extraction workflow is available in this checkout or public search results. The product name alone is no evidence of shared functionality. Obtain its source or owner confirmation before a standalone go decision. If Framed already supports the task, merge or reuse that code path.

**Free alternatives inspected on 14 October 2026.** [TOEA](https://toea.com/video-frame-extractor) offers local browser decoding, range and count controls, midpoint sampling, numbered timestamped PNGs, and a ZIP. [OmniKit](https://omni-kit.com/video-frame) offers local browser decoding, single or batch capture, PNG/JPG/WebP, previews, individual downloads, and a full ZIP; its current UI shows up to 60 frames. The [MIT browser extractor](https://github.com/marianohernando/video-frame-extractor) offers local FFmpeg.wasm processing and ZIP export, with a larger runtime download and SharedArrayBuffer requirement. These are strong free options. Their public pages and source were inspected; the same clip was **not** run through their completed export flows, so output quality, processing time, and upload behavior during capture are unverified. A Chrome attempt to load a local sample into TOEA and OmniKit was rejected by automatic approval review because the sample's sensitivity and authorization for those sites were not established.

**Possible gap, not a validated claim.** TOEA's described flow downloads all requested frames. OmniKit's current page presents individual frame downloads or the whole batch ZIP. The prototype lets a user inspect a batch, deselect unwanted stills, and download one ZIP of the retained frames; it also offers interval sampling and distinguishes requested from reported decoded time. This matches a [public user request for selected-frame batch export](https://www.reddit.com/r/vfx/comments/1lzmb76/i_made_a_web_tool_for_video_files_that_lets_you/), but that request does not establish demand for this product or prove either competitor cannot accomplish it another way. Confirm the gap by running the same short recording and creator footage tasks in the alternatives and, if available, observing target users.

**Website reuse.** The [One Horizon website integration](https://github.com/onehorizonai/one/tree/feature/video-frame-extractor/apps/ui/website/src/app/%28.%29/video-frame-extractor) already provides the `/video-frame-extractor` page. Its client component imports `App` from `@onehorizon/video-frame-extractor/react`; the website dependency points to the extractor repository, rather than copying its processing code. That branch also adds sitemap, `llms.txt`, `llms-full.txt`, footer discovery, and a browser route test. The integration has not been established as deployed publicly.

**Remaining gate.** Confirm Framed ownership and capabilities, run both competitor export workflows with authorized non-sensitive clips, and record the time, steps, output, and network behavior. Then choose go, merge, or no-build. Broader browser, codec, rotation, variable timing, and memory checks are also outstanding before expanding compatibility claims.
